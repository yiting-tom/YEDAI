## 三十秒版本

這是一支**量測工具**，不是產品。它存在的唯一目的是回答：

> OKF concept 的文字主體是機台 id / 製程 id / flow 等專有字詞。
> 一般斷詞會把 `TEL-05` 切成 `tel` + `05`，讓它與 `TEL-06` 幾乎無法區分。
> **識別碼需不需要特別處理？需要的話，斷詞層就夠，還是必須維護實體字典？
> 還是關鍵字檢索本身就不夠，得再加一條稠密腿？**

用五組消融量它：

```
A  天真 BM25F（識別碼被切碎）      ← 水位線
B  A + 識別碼保護斷詞              ← 隔離「斷詞層」的貢獻
C  B + 實體字典匹配加權            ← 隔離「字典」的額外貢獻
D  純稠密向量檢索                  ← 關鍵字腿整個落空的那些查詢
E  RRF(C, D)                       ← 隔離「融合」的額外貢獻
```

D/E 需要向量庫（`yedai embed`）。**沒有向量時它們是不可用，不是退化成 C**——
靜默退化會讓報告顯示「稠密腿沒有帶來差異」，而真相是它根本沒有執行。

### 能下什麼結論，取決於有沒有標準答案

| 手上有什麼 | 讀哪個指標 | 能回答 |
|---|---|---|
| 只有語料 | `mode_overlap` 的 jaccard / kendall tau | 五個模式的結果**有沒有不一樣**。`A-B` 接近 1 → 斷詞層沒作用；`B-C` 接近 1 → 字典不值得維護；`C-E` 接近 1 → 融合不值得那筆 embedding 費用 |
| 語料 + 內部 LLM | `evaluation` 的 recall@k / MRR | **哪一個比較對**。先看 `symptom` 那一欄——識別碼式查詢上 A/B/C 佔優是預期內的，沒有資訊量 |

`mode_overlap` 永遠答不出「哪一個比較好」，因為它沒有標準答案。這是這個實驗最根本的
天花板，而評估集（[evaluation.md](./evaluation.md)）是唯一拆掉它的方法。

在真實語料上跑出來的那份報告不含任何內容，可以直接分享。

### 語料是分層的

四類查案知識各自是一個獨立索引（或查表資源），因為它們該用不同的檢索方式：

| 層 | 性質 | 檢索 |
|---|---|---|
| 查案心法 | 自由文字、量大、無固定格式 | 真正的文字檢索。五模式在這一層完全對症 |
| 已結案 | 固定格式、持續累積 | 同格式文件比對。識別碼是主訊號，文字只是其中一維 |
| 缺陷登錄 | 每個 defect 一條 | 同時是實體字典的來源，其他層依賴它 |
| defect → 判斷方法 | 每個 defect 一條，部分填充 | **查表，不進索引** |

**分層不是整理上的偏好。** 混在一份統計裡，持續累積的那一層每長大一次，其他層的
排名就漂移一次——沒有任何變更、沒有任何測試會紅，檢索品質卻退化了。實測：同一份
文件、同樣的查詢，另一層灌入 60 篇之後 BM25 分數從 0.50 掉到 0.027。

檢索預設**分層回傳**，不跨層排序：RRF 融合的前提是兩份排名在回答同一個問題，
跨模式滿足，跨索引不滿足。設定與重建順序見 [indexing.md](./indexing.md#2-設定)。
