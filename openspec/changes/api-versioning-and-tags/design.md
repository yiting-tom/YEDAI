## Context

十個端點，兩個標籤，其中一個裝了七個。互動式文件頁的分組本來應該是**使用指引**——
看到分組就知道該用哪一組——但目前 `search` 這組把「找東西」「取內容」「導航」「回饋」
全部混在一起，等於沒有分組。

版本方面，服務目前對「我是誰、我相容什麼」完全沉默。索引格式已經升過兩次
（1→2→3），每次都要重建，但除錯時無法從服務端得知任何版本資訊。

## Goals / Non-Goals

**Goals:**

- 讓文件頁的分組本身傳達「什麼時候用哪一組」
- 建立版本前綴，使日後的破壞性變更可以並行提供新舊契約
- 讓服務能回答「我跑的是哪一版、索引相容嗎」

**Non-Goals:**

- 不提供 `/v2`，也不建立版本協商機制——只是把門開好
- 不做內容協商式版本化（`Accept` 標頭）
- 不改變任何端點的行為、參數或回應結構——**純路徑與分類變更**

## Decisions

### D1. URL 前綴，不是標頭協商

| | **URL 前綴（採用）** | `Accept` 標頭協商 |
|---|---|---|
| 可見性 | 一眼看出版本 | 藏在標頭裡 |
| curl / 瀏覽器 | 直接可用 | 每次都要加標頭 |
| 快取與日誌 | 天然分離 | 需設 `Vary` |
| agent 工具定義 | URL 寫死即可 | 需要額外約定 |

這是給人與 agent 用的內部工具，可見性與 curl 友善度遠比 URL 美觀重要。

### D2. `/healthz` 與 `/version` 不版本化

它們描述的是**服務本身**，不是 API 契約。監控探針與部署腳本不該因為 API 從
v1 升到 v2 就失效——那會讓版本升級的成本外溢到基礎設施。

`/v1/stats` 則相反：它描述的是**語料**，回應結構屬於 API 契約的一部分，因此版本化。

### D3. 硬切換，不保留根路徑別名

專案只有四個 commit，唯一的消費者是使用者本人，尚無任何 agent 在生產環境依賴這組 URL。

保留別名的代價：文件頁出現重複條目、每個端點兩條路由要維護、而且「舊路徑何時移除」
會變成一個永遠不會被處理的待辦。308 轉址則會讓不帶 `-L` 的 curl 腳本安靜失敗——
比直接 404 更難察覺。

現在硬切換的成本，遠低於三個月後有 agent 依賴時再切換。

### D4. 五個標籤，依「agent 的工作流」切分

```
retrieval  找到東西        search / grep
content    取得內容        concept / concepts / asset
graph      沿關聯導航      neighbors
telemetry  量測與回饋      feedback / report
ops        服務與語料狀態   healthz / version / stats
```

前三類正好對應建議流程（search → get → neighbors），所以分組本身就是流程說明。
`telemetry` 獨立出來很重要——那兩個端點服務的是「量測實驗」而非「使用系統」，
混在檢索裡會讓 agent 誤以為該呼叫它們。

每個標籤帶 `description`，在文件頁的分組標題下方顯示。

### D5. `/version` 一次回報四個版本

```
package        套件版本（pyproject）
api            API 版本（URL 前綴）
index_format   本程式支援的索引格式版本
index          目前載入索引的格式版本與簽章；未載入時為 null
```

分開是必要的：索引格式升級與套件版本沒有對應關係，而「服務支援 v3、載入的索引是 v2」
正是最需要一眼看出的除錯情境。索引未載入時仍須可回應——這個端點的用途之一
就是診斷載入失敗。

### D6. 以 `APIRouter(prefix=...)` 統一掛載

不逐一改寫十個裝飾器的路徑字串。前綴集中在一處，日後要開 `/v2` 只是再掛一個 router。

路由宣告順序的既有約束不變：`/concept/{concept_id:path}/asset` 與
`.../neighbors` 仍須宣告在 `/concept/{concept_id:path}` 之前。

## Risks / Trade-offs

- **既有 curl 腳本與書籤失效** → 這是刻意的破壞性變更；README、docs 與 commit 訊息
  明確標示，並在 `/healthz` 保持不變以免監控受影響
- **文件頁分組是否過細**（`graph` 只有一個端點） → 該端點的用途與 `content` 有本質差異
  （導航 vs 取用），且後續的 `neighbors` 篩選與寫入路徑會落在同一組
- **`/version` 洩漏版本資訊** → 本工具設計為本機使用，且版本號不構成敏感資訊
- **未來 `/v2` 的遷移路徑未定義** → 本變更只建立前綴機制，遷移策略待實際需要時再訂

## Open Questions

- `/v1/stats` 是否該進一步拆成「語料統計」與「索引狀態」兩個端點——目前混在一起，
  但兩者的變動頻率與消費者不同
