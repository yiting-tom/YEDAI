- [x] 14.1 `ConceptOut.generated` 宣告為 `str` 但模型是 `bool | None` → 所有內容端點對
      `generated: true` 的語料回 500。**main 上就有的缺陷**，合成語料每一篇都會觸發。
      測試看不到，因為 `conftest.write_concept` 從不寫這個欄位
- [x] 14.2 `Runtime.load` 每層各開一個 qdrant client → 本機檔案模式的獨佔鎖讓第二個
      有向量的層炸掉整個載入。**這次改動引入的**；目標部署形態（多層各自 collection）
      一旦有兩層跑過 embed 就完全起不來。改為 `VectorBackend` 共用單一 client
- [x] 14.3 跨層 `concept_id` 相撞時行為未定義：批次回重複、取全文靠字典順序、
      融合對同一份文件重複加權。改為先歸屬再取、宣告順序決定歸屬、融合只計一次；

## 17. 層要自己說明自己

分層做完之後才發現的缺口：agent 只看得到索引**名稱**——一個設定檔裡的任意鍵。
沒有任何地方說明那一層裝什麼、什麼時候該用它。`type` 幫不上忙（它是每份文件的
類型，與「這層是什麼」是兩個正交的軸）。

- [x] 17.1 索引宣告新增 `description` 與 `when_to_use`。前者說「這是什麼」，
      後者說「你什麼時候需要它」——agent 要的是後者
- [x] 17.2 `/v1/stats` 與 MCP `stats` 帶出這兩個欄位
- [x] 17.3 MCP `search` 的工具說明**從設定生成**。原本寫死「心法 / 已結案 / 缺陷登錄」
      當例子——在別人的部署上那就是錯的提示，而工具說明是 agent 唯一的手冊
- [x] 17.4 `indexes_without_description`：沒寫說明的層要被點名，呼叫端才知道自己在猜
- [x] 17.5 測試釘住「說明來自設定而非寫死」。這條抓到第二處漏網的寫死假設
      （空層的例子仍寫著「心法層為空」）
